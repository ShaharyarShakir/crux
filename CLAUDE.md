## Documentation Naming

Give every documentation file a meaningful name that says what the document is about, so a reader can tell its content from the filename alone.

- Use lowercase, hyphen-separated words, e.g. `cmake-package-build-pipeline-extraction.md`.
- A date or milestone number may prefix the name, but never replaces the description: `m4-cmake-package-build-pipeline-extraction.md`, not `m4-report.md`.
- Avoid generic names such as `report.md`, `notes.md`, `doc.md` or `final.md`.
