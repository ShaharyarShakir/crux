## Highlights

Crux v0.2.0 extends the source-first dependency pipeline with existing-project import and direct package sources while preserving the deterministic resolver, lockfile, build, install, and CMake integration model introduced in v0.1.0.

### Added since v0.1.0

- **Project Configuration & Toolchains**: standardized C/C++/Other initialization, project config validation, compiler/standard detection, and `CC`/`CXX` overrides.
- **Application Build & Run**: deterministic internal CMake generation, isolated Debug/Release application trees, recursive source discovery, argument forwarding, stdin passthrough, environment inheritance, and exit-code propagation.
- **Dependency Management**: transactional `crux add` / `crux remove`, lock preference preservation, automatic Debug dependency installation, and installed-package linking for local applications.
- **Official Catalog**: 50 package identities and 53 concrete versions, including a verified CMake-buildable tier and five reference applications.
- **Existing Project Import**: conservative `crux import` discovery for C/C++ sources, CMake and Makefile layouts, include roots, and multiple executable candidates, with Crux-managed `.crux/import.toml`.
- **Direct Package Sources**: Git (tag, branch, rev, or full commit), SHA-256-verified remote archives, and local package directories. Direct sources use the same catalog/resolver/lockfile/build/install/integration pipeline as registry packages.
- **Direct-Source Integrity**: Git refs resolve to immutable commits, locked commits are not silently upgraded, source conflicts and cycles are rejected, nested local paths are rebased, and Git/local sources receive real deterministic source-tree digests.

## Direct Sources Quickstart

```bash
# Git tag; the resolved commit is written to crux.lock
crux add util --git https://example.invalid/util.git --tag v1.2.3

# Git branch; the commit is locked until `crux lock --update`
crux add util --git git@github.com:org/util.git --branch main

# Remote archive; SHA-256 is mandatory
crux add util --url https://example.invalid/util.tar.gz \
  --sha256 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef

# Local package directory
crux add util --path ../local-util
```

Equivalent `crux.toml` syntax:

```toml
[dependencies]
util = { git = "https://example.invalid/util.git", tag = "v1.2.3" }
```

See [Direct Package Sources](../guides/direct-sources.md) for the complete grammar, lockfile semantics, moved-project behavior, and limitations.

## Installation

### One-Line Install (Linux x86_64)

```bash
curl -fsSL https://raw.githubusercontent.com/ShaharyarShakir/crux/main/install/install.sh | bash
```

The installer defaults to `v0.2.0` and still accepts `--version <tag>`.

### Nix / NixOS (Flake)

```bash
nix build github:ShaharyarShakir/crux
nix profile install github:ShaharyarShakir/crux
```

### Build from Source

```bash
git clone https://github.com/ShaharyarShakir/crux.git
cd crux
cargo install --path .
```

## Compatibility

- Existing `[dependencies]` entries that are plain SemVer strings continue to resolve from the active registry unchanged.
- `crux.lock` remains format version 1; source identities are canonical strings inside the existing `source = "..."` field.
- `crux lock --check` compares direct-source identity while ignoring acquisition-only Git commit differences.
- A package name may be provided by the registry or by one direct source, never by both.
- The repository `.gitignore` uses `/build/`, so `src/build/` Rust sources are tracked normally.

## Security Model & Sandboxing Disclosure

- External build tools (`cmake`, compilers) execute with ambient user privileges. No operating-system containerization or namespace sandbox (bubblewrap/seccomp) is active in v0.2.0.
- All external subprocesses use discrete argument vectors; no shell interpolation is performed.
- Git URLs and refs are validated, Git commands use null stdin and hard timeouts, and locked sources are checked out at the pinned commit.
- Remote archives require SHA-256 verification before extraction, with Zip Slip, symlink jail, and decompression-bomb protections retained.
- Full details are in [docs/reference/security-model.md](../reference/security-model.md).
