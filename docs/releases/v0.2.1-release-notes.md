# Crux v0.2.1 Release Notes

**Release**: v0.2.1  
**Release Date**: 2026-11-20  
**Tag**: `v0.2.1` (forward hotfix; tagging reserved for the repository owner)  
**Distribution**: GitHub Releases & GitHub Pages  

---

## Scope

Crux v0.2.1 is a **forward security/documentation hotfix** published after v0.2.0. It does not rewrite or move the v0.2.0 tag. **v0.2.0 remains tagged and published**, and its release artifacts and installer remain available. Users who consume **untrusted direct sources** (Git repositories, remote archives, or local package trees they do not control) should **upgrade to v0.2.1**.

The v0.2.0 release introduced direct package sources and shipped a working installer. A read-only audit of the released v0.2.0 tree identified the remaining issues addressed here.

---

## Fixed in v0.2.1

### Security

- **Direct/path source tree symlink escape (HIGH)**: Source-tree validation for direct Git and local-path sources now rejects symlinks that resolve outside the validated source root before hashing, copying, or building. Archive extraction and staged installation keep their existing symlink jail.
- **HTTPS-only archive enforcement (MEDIUM)**: Remote source archives must use HTTPS; unencrypted `http://` archive URLs are rejected. Documentation no longer claims that plain HTTP is accepted.
- **Registry Git `rev` validation (MEDIUM)**: Invalid registry and direct-source Git `rev` values are validated before subprocess execution, so malformed revisions produce an actionable error instead of a panic.

### Documentation & CLI alignment

- **`crux integrate cmake --output <path>` (HIGH)**: The flag was advertised in the documentation but rejected by the v0.2.0 CLI. The CLI now accepts it; the default output remains `.crux/cmake/CruxDependencies.cmake`. The CLI reference includes an example.
- **Direct-source security documentation**: The security model and site security page now cover direct sources explicitly: Git argv-only execution with null stdin and timeouts, refs resolved to immutable commits, SHA-256 verification before extraction, real deterministic tree digests, HTTPS-only archives, and registry-vs-direct / direct-vs-direct conflict and cycle checks.
- **Roadmap, checklist, and report alignment**: Milestone and release-checklist status now reflect that M24 was released in v0.2.0 and hardened in v0.2.1, with the M25 hotfix recorded as complete. The M24 report carries an amendment distinguishing its historical authoring-time snapshot from the current hotfix status and is indexed from the documentation lists.
- **Corrections**: The extraction ceiling is documented as 1 GB uncompressed (not 500 MB). Digest verification is described as SHA-256 comparison after normalization; no constant-time claim is made. Stale "M19 application build engine" labels were replaced with the neutral "application build engine" label in current docs. Website footer anchors now point to real architecture headings.

## Compatibility

- `crux.lock` remains format version 1; existing v0.2.0 lockfiles continue to work.
- Plain SemVer registry dependencies and all v0.2.0 direct-source manifest forms remain supported.
- The installer defaults to `v0.2.1` and still accepts `--version <tag>` to select another release, including `v0.2.0`.
- No user manifest or lockfile migration is required.

---

## Security Model & Sandboxing Disclosure

External build tools (`cmake`, compilers) still execute with ambient user privileges. **No OS-level containerization or namespace sandbox is active in v0.2.1.** Direct sources are validated and use safe subprocess handling, but an untrusted source tree can still execute external build tools with the privileges of the invoking user. Only use direct sources from origins you trust, or run Crux inside your own isolated environment.

Full details are in [docs/reference/security-model.md](../reference/security-model.md) and the [Direct Package Sources guide](../guides/direct-sources.md).
