# Crux v0.2.1 Release Notes

**Release**: v0.2.1  
**Release Date**: 2026-11-22  
**Tag**: `v0.2.1` (forward release; tagging is done by the repository owner)  
**Distribution**: GitHub Releases & GitHub Pages  

---

## Scope

Crux v0.2.1 is a **security and developer-experience release** published after v0.2.0. It does not rewrite or move the v0.2.0 tag. **v0.2.0 remains tagged and published**, and its release artifacts and installer remain available.

Users who consume **untrusted direct sources** (Git repositories, remote archives, or local package trees they do not control) should **upgrade to v0.2.1**. One fixed issue, a tar symlink-chain extraction escape, is rated critical.

v0.2.1 also adds a Cargo-style terminal experience: status lines, structured build diagnostics, download progress, and `--color` / `-q` / `-v` / `-vv`. See [Terminal output](#terminal-output-and-diagnostics).

## Fixed in v0.2.1

### Security: archives and source trees

- **Tar extraction symlink-chain escape (CRITICAL)**: A tar archive could use a chain of symlinks to write files outside the extraction directory. Extraction now resolves the physical destination of every entry and rejects any chain that leaves the extraction root.
- **Direct/path source tree symlink escape (HIGH)**: Source-tree validation for direct Git and local-path sources rejects symlinks that resolve outside the validated source root before hashing, copying, or building.
- **HTTPS-only archive enforcement (MEDIUM)**: Remote source archives must use HTTPS; `http://` archive URLs are rejected. Archive URLs that embed credentials are rejected.
- **Archive unwrapping edge cases**: A nested root such as `pkg/pkg/…` no longer fails, and a top-level hidden file is no longer silently overwritten by a same-named file from the wrapper directory; collisions are refused.
- **`tar -C dir .` archives** (whose first entry is `./`) are now accepted. This is a compatibility fix; non-directory entries with an empty path are still rejected.

### Security: lockfile and source integrity

- **Lockfile checksums are verified.** Previously a checksum recorded in `crux.lock` was never compared with the acquired source. `crux fetch`, `crux build` and `crux install` now verify it and fail on a mismatch.
- **Re-locking rejects changed checksums.** `crux lock`, `crux add` and `crux remove` refuse to rewrite a checksum for an unchanged name, version and source identity. `crux lock --update` accepts the change explicitly and prints a warning for each one.
- **`crux lock --check`** reports checksum drift between the lockfile and the current sources.
- **Legacy Git checksums** (the earlier tree-digest format) produce a one-time warning per package and are migrated to the current format by a normal `crux lock`, only when the old digest provably describes the same content. A second `crux lock` is byte-identical.
- **Path dependencies are built from a verified snapshot.** They remain mutable by design and are not covered by the immutability guarantees of pinned Git or archive sources; this is documented.
- **Deterministic source digests.** Tree digests no longer depend on the local umask or on non-UTF-8 file names. Nested `build/` and `target/` directories inside packages are no longer discarded.
- **Registry Git `rev` validation (MEDIUM)**: Invalid `rev` values are rejected before any subprocess runs, with an actionable error instead of a panic.

### Security: Git, network and subprocesses

- **Git option injection in registry clone (MEDIUM)**: Registry URLs are validated and passed after `--`, so a value such as `--upload-pack=…` can no longer be treated as a Git option.
- **Git URL policy**: `http://`, `git://`, transport-prefixed URLs (`ext::`, `fd::`), URLs with whitespace, URLs beginning with `-`, and dependency URLs with embedded credentials are rejected. Git subprocesses run with `GIT_ALLOW_PROTOCOL=https:ssh:file`.
- **Credentials are redacted** in `crux registry list` / `add`, in Git errors, and in progress output. Newly created `config.toml` files are mode `0600`.
- **Timeouts cover helper processes.** When a Git or CMake step times out, its descendant processes are also killed. Previously a stuck helper such as `git-remote-https` could keep running after the timeout.
- **Registry Git operations have timeouts**, and the automatic official-registry bootstrap never prompts for credentials.
- **Download timeouts apply to stalls, not total time**, so large downloads that are still making progress are no longer cut off.
- **Non-default Git branches** now resolve correctly.

### Security: installer and CI

- **Installer checksum parsing is strict.** `SHA256SUMS` lines must be `<64 hex>  <name>`, the file name is compared literally, and exactly one entry is required. Previously an unanchored match could accept a line for a different file such as `….tar.gz.sig`. The version tag is validated, and only `https://` and `file://` base URLs are allowed.
- **Release workflow injection fixed.** Workflow inputs and tag names are passed through `env:`, validated, and never interpolated into scripts that run with the release token.
- **Workflow permissions reduced.** All actions are pinned to commit SHAs, CI and build jobs are read-only, write scopes are limited to the release and deploy jobs, the wildcard `safe.directory` was removed, and checkouts no longer persist credentials.

### Reliability

- **One atomic-write routine** is used for the lockfile, config, manifest edits, build metadata and CMake integration output. It creates temp files exclusively, preserves permissions (a `0600` `crux.lock` stays `0600`), and cleans up on failure.
- **Build output is streamed to the build log** as it is produced and only a bounded tail is kept in memory, so large builds no longer buffer all CMake and compiler output.
- **Closed pipes** such as `crux resolve | head -1` end quietly instead of producing an error.

## Terminal output and diagnostics

All new status output goes to **stderr**. Command results on **stdout** are unchanged, so existing scripts keep working. See the [terminal output guide](../guides/terminal-output.md).

- **Status lines**: `Compiling`, `Finished <profile> profile in Xs`, `Running`, `Installing`, `Downloaded`, `Fetched`. Verbose modes add cache hits, URLs, checksum verification and extraction.
- **Build failures** show a structured diagnostic: package and version, stage (CMake configuration, or compilation and linking), exit status, build directory, log path and the exact command. The original CMake and compiler output follows unmodified, with long output shortened in the middle unless `-v` is given. Crux does not parse or guess causes. This replaces the former `Build failed!` message.
- **Download progress**: a single in-place line on a terminal, with a percentage only when the server reports a size; one line per download when output is piped.
- **Global options**, accepted before or after the command (not after `--`): `--color auto|always|never`, `-q` / `--quiet`, `-v` / `--verbose`, and `-vv` to stream CMake and compiler output live.
- **Color precedence**: `--color`, then `CLICOLOR_FORCE`, then `NO_COLOR`, then whether stderr is a terminal and `TERM` is not `dumb`. Piped output never contains escape codes unless color is forced.
- **Build logs** now begin with the command, contain stdout and stderr in the order produced, and end with the exit status.

## Documentation & CLI alignment

- **`crux integrate cmake --output <path>` (HIGH)**: The flag was documented but rejected by v0.2.0. The CLI now accepts it; the default remains `.crux/cmake/CruxDependencies.cmake`.
- **Security documentation**: The security model and site security page cover direct sources, the Git URL policy, lockfile verification, installer checks and workflow hardening.
- **Roadmap, checklist and reports** reflect the v0.2.1 work. A full account of the security work is in [the remediation report](../reports/2026-11-21-source-security-remediation-report.md).
- **Corrections**: The extraction ceiling is documented as 1 GB uncompressed. Digest verification is described as a SHA-256 comparison; no constant-time claim is made. The website footer links point to real headings.

## Compatibility

- `crux.lock` remains format version 1; existing v0.2.0 lockfiles continue to work. Legacy Git checksums produce a warning and migrate on `crux lock`.
- **Behavior changes to be aware of:**
  - Manifests or lockfiles that use `http://` or `git://` Git URLs, or that embed credentials in a Git or archive URL, now fail with an actionable error.
  - Re-locking fails when a checksum changes for an unchanged package identity; use `crux lock --update` after confirming the change is intended.
  - `crux build` and `crux run` print `error: package compilation failed` with a diagnostic instead of `Build failed!`.
  - Build logs use the new format described above.
- Plain SemVer registry dependencies and all v0.2.0 direct-source manifest forms remain supported.
- The installer defaults to `v0.2.1` and still accepts `--version <tag>`, including `v0.2.0`.
- No user manifest migration is required.

## Known limitations

- Registry update and dependency resolution keep their existing messages and have no new status lines.
- Sources fetched while loading the catalog (direct Git or path dependencies during `lock` / `resolve`) do not report progress.
- Compilation and linking are reported as a single stage.
- `-q` suppresses Crux's status lines but not the existing stdout summaries.
- Package builds have no timeout.
- The CLI reference lists exit code 2 for argument errors, but the binary exits with 1.

## Security Model & Sandboxing Disclosure

External build tools (`cmake`, compilers) still execute with ambient user privileges. **No OS-level containerization or namespace sandbox is active in v0.2.1.** Direct sources are validated and use safe subprocess handling, but an untrusted source tree can still execute external build tools with the privileges of the invoking user. Only use direct sources from origins you trust, or run Crux inside your own isolated environment.

Full details are in [docs/reference/security-model.md](../reference/security-model.md) and the [Direct Package Sources guide](../guides/direct-sources.md).
